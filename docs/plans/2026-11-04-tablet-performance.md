# Shared tablet performance implementation plan

Goal: remove confirmed wasted capture/render work and recover tracking safely, then publish an isolated preview for the user's solo tablet playtest.

Approved design: the user's “go ahead” follows the 4November code review and its recommended shared performance pass. Preserve gameplay, visual benchmark, scoring, calibration and short deliberate gesture safeguards. Implement bounded latest-frame capture, controlled worker recovery, video-frame-driven texture updates, shared graphics downgrade including shadows and exportable local diagnostics. Worker-safe/lighter inline pacing addresses UI contention; actual hardware gains remain unmeasured. No new art, dependencies or production merge before tablet feedback.

Architecture: keep one renderer and current scene ownership. Extract small testable scheduling/recovery and camera-frame helpers. Quality is shared session state with an observable grade and bounded pixel budget; graphics features consume the same grade. Capture/results carry truthful sequence/time; never loosen stale limits merely to mask latency. Diagnostics use numbers only, remain local/exportable and do not depend on /report.

1. Tracking (independent domain, pose.ts/pose.worker.ts): write RED tests for single capture-in-flight, bounded output/latest timestamps and release, failed/delayed reply recovery, finite retries and stale-worker rejection. Implement bounded latest capture and try/finally error replies; recovery must close old workers/bitmaps and require real reacquisition. Pace inline fallback with a lighter measured budget and keep captured-vs-receipt timing visible. Test copied, direct fallback, disabled APIs, initialization failure and paired ownership; no duplicate long-running capture loops.
2. Camera texture: RED tests verify a10fps source cannot request60uploads, callbacks cancel after scene disposal, fallback handles currentTime and updates no more than once per frame, and dimension changes survive. Shared helper owns callback and texture update; replace shared mirror, Freeze and Shape paths without changing shader/exposure/alignment. Run real-camera fake-device browser counter check.
3. Graphics quality: RED rules cover pixel-count cap and monotonic measured downgrade; existing lean changes are applied consistently to current/new Jab/Goalie shadow lights and render resolution. Keep the quality benchmark on capable devices. Disable expensive shadows in Performance and use existing contact blobs. No game timing/scoring changes.
4. Diagnostics: retain recent frame/tracker/camera/profile stats locally; export a small JSON from existing Tracking diagnostics. Never save landmarks/video; don't add an external collector. Run only on deliberate user action or bounded cadence, not per-frame DOM/JSON work.
5. Integrate pure tests in npm check; run full check/build once. Focused browser checks measure bounded captures, recovery, video upload ratio, low-tier shadow work and actual solo game transitions; inspect screenshots. Run the installed standard game client. Independent read-only review before commit/push; resolve real findings.
6. Whitelist/hash-copy exact tested files into attached clean branch codex/moon-tablet-performance, create and attach PR to master and check Vercel preview at exact head. Provide preview and concise tablet test instructions; leave production unchanged pending real-device feedback.
